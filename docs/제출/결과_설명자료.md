# 결과 설명자료

제주빅데이터센터 빅데이터 분석·컨설팅 지원 보조 Agent([호리창술] 송준희)의 문제 정의, 구조, 검증, 한계, 센터 활용 방안을 적는다.
실행 방법은 `README.md`, 자료는 `docs/제출/데이터_활용_명세.md`와 `notebooks/01_데이터_확인.ipynb`에 있다.

## 1. 문제 정의
- 제주테크노파크는 센터·데이터허브 데이터로 시각화 분석과 데이터 활용 컨설팅을 지원한다(공고 제2026-116호).
- 2026년 1차 모집은 선착순 10건 내외다. 2025년 실적은 컨설팅 7건, 분석 5건이다(보도자료 2026-04-28).
- 2020~2024년 지원 과제 53건에는 '신규 매장 입지 조사를 위한 유동인구 시각화 분석' 같은 상권 분석이 포함됐다(보도자료 2025-04-30).

| 단계 | 현재 | 이 Agent로 바꾸는 것(제안) |
|---|---|---|
| 신청 | 선착순 10건 내외라 신청하지 못한 도민은 분석 지원을 받지 못한다 | 신청 없이도 센터 PC에서 동네 상권 자료와 보고서(PDF)를 직접 확인한다 |
| 사전 면담 | 신청자 모두와 담당자가 면담한다 | 도민이 Agent 결과를 먼저 확인하고, 결과로 해결되지 않는 요청만 면담한다 |
| 분석·컨설팅 | 담당자가 요청마다 분석을 직접 수행한다 | 담당자는 Agent 보고서를 면담 자료로 쓰고, 추가 분석은 통계 기법 13종·상세 분석으로 화면에서 실행한다 |
| 결과 송부 | 2주 이내에 보낸다 | 질문 직후 답 화면과 보고서 PDF가 나온다 |

- 사용자는 두 부류다. 1차 사용자는 센터를 찾은 소상공인·예비창업자(도민)이고, 2차 사용자는 센터 담당자다.
- Agent는 창업할지 말지 추천하거나 결정하지 않는다. 판단에 쓸 근거(숫자·순위·출처·한계)를 보여 준다.

## 2. 구조

### 2.1 처리 순서
질문은 먼저 **단계형 Agent**(`app/step_agent.py`)가 받는다. 로컬 모델(`qwen2.5:7b`)이 질문을 단계로 나누고(물은 일이 하나면 1단계), 단계마다 도구 하나(일반 답·통계 기법·업종 순위·앞 단계 비교·센터 자료 찾기·건너뛰기)와 하위 질문 문장을 고른다. 단계가 실패하거나 넘어가면 모델이 남은 단계를 한 번 다시 쓰고, 답을 내기 전에 빠진 요청이 있는지 스스로 확인한다. '여러 가지를 물었을 확률'이 0.5 미만이면 단계 목록을 보여 주고 멈춘다. 직전 질문·결론 2개를 받아 이어지는 질문('그럼 애월읍은?')에 쓴다. 코드는 차례마다 끝난 단계와 결과, 지금 단계, 남은 단계, 앞 결과(1위 동네·1위 업종)를 보여 주고, 남은 단계가 있으면 답을 내지 않는다. 업종·지명·지표의 같은 뜻 낱말을 목록 값으로 바꾸고, 잘못된 호출에는 고칠 값을 돌려주며, 기법을 뜻하는 말이 없는 단계에는 통계 기법 도구를 보이지 않는다. 일반 답 단계는 아래 1~9의 처리를 하위 질문 하나에 돌린다. 1단계면 원래 질문을 그대로 넘긴다.

1. **질문 나누기**: 한 질문에 묻는 것이 여럿이면 코드가 하위 질문으로 나눈다. 앞 조각의 동네·업종과 앞 결과('1위 동네')를 뒤 조각에 넘긴다(`app/split.py`).
2. **M1 질문 해석**: 문장 임베딩(Ollama `bge-m3`) + 분류기로 질문 종류·동네·업종·지표를 읽는다. 임베딩을 쓸 수 없으면 사전 규칙으로 해석한다.
3. **M2 계획 선택**: 질문 종류별 계획 표(`app/planner.py`)로 자료와 계산 순서를 정한다. 해석이 애매하면 이해 카드에 '확인이 필요해요'로 표시한다(`JEJU_CLAUDE=auto`면 Claude가 정해진 종류 13개 중에서 고름, `app/plan_agent.py`).
4. **M3 작업 지시서·넘김**: 계산 순서를 확정한다. 일반 경로가 풀지 못한 질문(계산 실패, 분류기만 범위 밖으로 본 질문)은 Agent에게 넘긴다(`JEJU_CLAUDE=auto`면 Claude가 넘길지 판정).
5. **Sub 실행(S1~S6)**: 조회, 기술 통계, 예측 모델, 차트, 결합, 통계 판정을 Python 코드로 계산한다.
6. **질문 담당 Agent**: 코드가 질문과 계산 결과의 어긋남(기간·조건·순위·지표·범위 밖 판단·동네 없음)을 찾아 선택지로 만들고, 로컬 모델(`qwen2.5:7b`)이 지금 답 그대로·안내 붙여 답하기·다시 계산·되묻기·범위 밖·기법으로 넘기기 가운데 하나를 고른다. 다시 계산하면 2~5단계를 새 해석으로 다시 돌린다. 다시 계산한 뒤에는 모델이 앞 답과 새 답을 견줘 되돌릴지 한 번 더 고른다. 최대 3번 되풀이하고(질문당 150초 상한), 다시 계산한 답에 질문의 동네가 없거나 앞 답이 지킨 질문의 기간·조건·지표를 잃으면 그 답은 쓰지 않는다(`app/question_agent.py`).
7. **검수·재실행**: 결과와 문장 속 숫자를 검사하고, 실패하면 재계획·재계산한다(2회까지). 해석 오류 후보는 오류 노트로 만들어 다시 읽히고, 남은 의심 칸은 화면에서 사람에게 확인받는다.
8. **결과 생성**: 결론 한 줄, 5칸 요약, 근거 차트, 출처, 보고서 PDF를 만든다. 대신 쓴 지표·업종 구분이 없는 값·없는 시점으로 답하면 무엇으로 대신했는지 코드가 문장으로 밝힌다(`result.honest_notes`).
9. **사용자 확인**: 기다리는 동안 화면에 지금 단계와 남은 단계를 보인다(`/api/ask/stream`). 답 위의 확인 카드는 Agent의 1차 결정, 다른 선택지 2~3개, 직접 적기 칸으로 이뤄진다. 모델이 선택 글자를 쓸 때의 토큰 확률로 선택지별 확률(Jev의 Choice 출력과 같은 모양)을 만들고, 1·2위 확률 차가 0.8 미만이면 답을 가리고 먼저 고르게 한다. 고른 선택지는 모델 판단 없이 다시 계산하고, 의견은 센터 담당자가 읽는 기록으로 남긴다.

### 2.2 Workflow와 Agent
- 구조를 한 줄로 쓰면 '코드가 정한 경로 안에서 로컬 모델이 단계마다 도구와 다음 행동을 고르는 Agentic Workflow'이다. 숫자 계산과 사실 검사, 평소 말투 질문의 단계 나누기는 코드가, 긴 요청의 단계 나누기와 단계마다의 도구 고르기·다음 행동의 선택은 로컬 소형 모델이 한다. 단계별 도구 고르기는 Claude Sonnet으로 대체한다(센터 운영은 항상, 제출본·데모는 API 보안을 위해 로그인 때만, 키나 인터넷이 없으면 7B). [Claude로 분석]도 Claude API를 쓴다.
- 구분 기준은 Anthropic, *Building effective agents*(2024-12-19)의 정의다. 다음에 부를 도구와 횟수, 결과를 보고 계속할지를 모델이 정하면 Agent, 코드가 정한 경로를 따르면 Workflow다. 2026-11-15까지 도민 질문 처리는 코드가 경로를 정하고 모델은 선택지 번호만 고르는 Workflow(routing·evaluator-optimizer)였다. 이 기준으로 보면 서비스 전체는 Agent 단계가 들어 있는 Workflow, 곧 Agentic Workflow다. 일반 질문과 평소 말투의 여러 단계 질문은 코드가 경로(평소 말투 질문은 원문 구절로 단계 나누기까지)를 정하고, 모델은 단계마다 도구와 다음 행동을 고른다. 모델이 단계 목록·도구·건너뛰기를 스스로 정하는 Agent 동작은 긴 여러 단계 요청과 담당자의 [Claude로 분석]에서 일어난다. 7B 로컬 모델의 판단 정확도(옛 도구 루프 판정 17/60)를 보고 경로를 코드 쪽에 두었다.
- 2026-11-16부터 도민 질문은 단계형 Agent가 받는다. 모델이 단계 목록, 단계마다의 도구와 하위 질문, 건너뛸지를 정하고, 코드는 상태를 보여 주고 검사한다. 같은 모델로 판정용 여러 단계·기법 + 일반 질문 60개에서 모든 단계를 처리한 문항이 옛 도구 루프 17에서 41로 늘었다(새 구성만 맞힘 30·옛 구성만 6, p < 0.001). 답 문장까지 보는 엄격한 채점으로는 13 → 32다. 비교·업종 순위 도구, 다시 계획, 자기 확인, 단계 수 확인 카드, 대화 맥락을 더한 뒤 46/60·37/60, 11/18 결함 수정 뒤 최종 49/60·43/60이다(옛 구성 대비 35 대 3, p < 0.001. 11/16 중간 측정은 앞 구성과 8 대 3, p 0.23). 단순 질문은 1단계로 질문 담당 Agent에 그대로 가서 일반 질문 판정은 226/277이다.
- 계산 자체는 정해진 순서로 도구를 실행한다. 숫자 계산을 LLM에 맡기지 않아 같은 계산에는 같은 숫자가 나온다.
- 기본 경로에서 LLM이 판단하는 곳은 도민 질문의 질문 담당 Agent(`app/question_agent.py`), 상세 분석의 분석 담당 Agent(`app/analyst.py`), 넘겨받은 질문의 도구 루프다. 질문 담당 Agent는 계획 표로 한 번 계산한 결과를 코드가 질문과 대조해 어긋남과 선택지를 만들면, 모델이 지금 답 그대로·안내 붙여 답하기·다시 계산·되묻기·범위 밖·기법으로 넘기기 가운데 하나를 고르는 일을 최대 3번 되풀이한다. 분석 담당 Agent는 센터 담당자가 요청을 처리하는 순서대로 ① 요청 이해(요청의 뜻으로 기법·자료 찾기·일반 질문을 고름) → ② 조건이 안 맞으면 대안 고르기 → ③ 계산 → ④ 도민 말 해석 → ⑤ 다음 분석 제안을 거친다. 로컬 모델(`qwen2.5:7b`)이 단계마다 한 번 판단하고, 코드는 판단을 검사하고 숫자를 계산한다. 기법 이름이 적혀 있어도 먼저 모델이 판단하고, 이름과 다르면 코드가 한 번 되묻는다. 이름이 없으면 질문 기록(RAG, `app/rag.py`)에서 비슷한 과거 요청 5개를 찾는다. 그 요청들이 받은 기법과 모델의 첫 판단이 크게 어긋나면 예시를 붙여 한 번 더 판단하게 한다. 마지막 판단은 모델이 하고 코드는 결과를 바꾸지 않는다. 지금 기록은 학습·조정용 문장 786개이고, 운영에서 질문이 쌓이면 담당자가 확인하거나 고친 요청을 기록에 더할 수 있다(색인을 다시 만드는 명령 `tools/rag_build.py`, 자동 반영은 아직 없음).
- 담당자가 [Claude로 분석]을 누른 요청은 Claude가 도구 5개(코드 작성·격리 실행 포함)로 푼다. `JEJU_CLAUDE=auto`면 Claude가 애매한 질문의 계획 선택과 넘김 판정도 맡는다. 두 판단은 정해진 선택지 안에서만 고르고, 같은 질문의 결정은 저장해 다시 쓴다(질문 담당 Agent의 판단은 저장하지 않는다).
- 도구 루프(Agent)는 LLM이 도구를 고르고 결과를 보고 다음 도구를 고른다. 단계 5회·90초 상한과 숫자 대조는 코드가 통제한다.

### 2.3 Tool/API

| 도구·API | 고르는 쪽 | 하는 일 | 실패하면 |
|---|---|---|---|
| 단계형 Agent(`app/step_agent.py`) | `qwen2.5:7b`(계획 1회 + 단계 수 확신 1회 + 단계마다 1회 + 자기 확인 1회, 실패하면 다시 계획 1회) | 단계 나누기, 단계마다 도구(일반 답·통계 기법·업종 순위·앞 단계 비교·센터 자료 찾기·건너뛰기)와 하위 질문 고르기, 다시 계획, 빠진 요청 확인 | 질문·앞 결과에 없는 동네는 질문의 동네로, 이미 시도한 요청은 다시 더하지 않음, 계획을 못 쓰면 코드의 질문 나누기, 여러 일을 잇는 표지 없이 쪼갠 계획은 1단계로, 한 단계에 두 번 실패하면 단계 문장 그대로 일반 답, 150초 상한 |
| 질문 나누기(`app/split.py`) | 프로그램 | 여러 단계 질문 → 하위 질문, 맥락·앞 결과 넘기기 | 나누지 않고 한 질문으로 처리. 앞 결과가 없으면 뒤 조각을 계산하지 않고 이유 표시 |
| M1 해석(`bge-m3`, Ollama) | 프로그램 | 질문 → 종류·동네·업종 | 사전 규칙 |
| `choose_plan` | Claude(`JEJU_CLAUDE=auto`) | 애매한 질문의 종류(13개 + Agent) | 분류기 결과. 고른 종류가 검수 규칙에 걸려도 분류기 결과 |
| `judge_route` | Claude(`JEJU_CLAUDE=auto`) | 일반 경로로 충분한지 / Agent로 넘길지 | 일반 경로 결과 |
| M3 작업 지시서(`app/runner.py`) | 프로그램 | 종류 → 계산 순서 | 일부만 답하고 이유 표시 |
| 질문 담당 Agent(`app/question_agent.py`) | `qwen2.5:7b`(차례마다 1회, 최대 3회) | 질문·결과 어긋남 → 선택지 → 지금 답 그대로·안내 붙여 답하기·다시 계산·되묻기·범위 밖·기법으로 넘기기 | 모델 실패 시 지금 답 그대로, 다시 계산한 답에 물은 동네가 없거나 질문의 기간·조건·지표를 잃으면 버림, Ollama가 없으면 계획 표 답 |

## 7. 센터 활용 방안
- **센터 PC 탑재**: `scripts\setup_windows.bat`으로 한 번 설치하고(이때만 인터넷 필요) `scripts\run_windows.bat`으로 실행한다. 설치 뒤에는 인터넷 없이 표 파일과 PC에 설치한 모델(`bge-m3`·`qwen3:1.7b`·`qwen2.5:7b`)로 동작한다. 방문자가 바뀌면 창을 닫거나 사이드바 '새 상담 시작'을 누른다.
- **도민 방문 상담**: 도민이 동네와 업종을 골라 결과와 보고서 PDF를 먼저 확인한다. 결과로 해결되지 않는 요청만 담당자 면담으로 넘긴다.
- **담당자 컨설팅**: Agent 보고서를 면담 자료와 결과 초안으로 쓴다. 추가 분석은 사이드바 '통계 기법으로 보기'와 상세 분석으로 화면에서 실행한다.
- **센터 자료 연결**: 화면의 '자료 요청' 카드가 필요한 센터 자료와 조회 조건을 안내한다. 담당자가 센터 PC에서 조회한 CSV를 '센터 자료 넣기'로 넣으면 그 자료로 다시 계산한다.
- **Claude API**: 센터 PC는 Claude API를 기본으로 쓴다. 센터 운영에서는 `.env`에 `JEJU_STEP_CLAUDE=always`를 적어 여러 단계 질문의 도구 고르기에 항상 Sonnet을 쓴다(센터 PC의 VRAM 3GB에서 7B 일부를 CPU로 계산해 느려지는 것을 피함). 제출본과 데모는 API 보안을 위해 담당자(심사용) 계정으로 로그인한 요청에만 쓴다(기본 `login`). 여러 단계 질문의 단계별 도구 고르기(Sonnet, 자동)와 상세 분석의 [Claude로 분석](목록에 없는 분석의 코드 작성 등)이다. 키가 없어도 질문 나누기와 로컬 모델 Agent로 같은 구조가 돈다. 키에는 사용 한도를 먼저 설정한다.
