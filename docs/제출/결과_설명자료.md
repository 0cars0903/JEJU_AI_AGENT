# 결과 설명자료

제주빅데이터센터 빅데이터 분석·컨설팅 지원 보조 Agent([호리창술] 송준희)의 문제 정의, 구조, 검증, 한계, 센터 활용 방안을 적는다.
실행 방법은 `README.md`, 자료는 `docs/제출/데이터_활용_명세.md`와 `notebooks/01_데이터_확인.ipynb`에 있다.

## 1. 문제 정의
- 제주테크노파크는 센터·데이터허브 데이터로 시각화 분석과 데이터 활용 컨설팅을 지원한다(공고 제2026-116호).
- 2026년 1차 모집은 선착순 10건 내외다. 2025년 실적은 컨설팅 7건, 분석 5건이다(보도자료 2026-04-28).
- 2020~2024년 지원 과제 53건에는 '신규 매장 입지 조사를 위한 유동인구 시각화 분석' 같은 상권 분석이 포함됐다(보도자료 2025-04-30).

| 단계 | 현재 | 이 Agent로 바꾸는 것(제안) |
|---|---|---|
| 신청 | 선착순 10건 내외라 신청하지 못한 도민은 분석 지원을 받지 못한다 | 신청 없이도 센터 PC에서 동네 상권 자료와 보고서(PDF)를 직접 확인한다 |
| 사전 면담 | 신청자 모두와 담당자가 면담한다 | 도민이 Agent 결과를 먼저 확인하고, 결과로 해결되지 않는 요청만 면담한다 |
| 분석·컨설팅 | 담당자가 요청마다 분석을 직접 수행한다 | 담당자는 Agent 보고서를 면담 자료로 쓰고, 추가 분석은 통계 기법 8종·전문가 모드로 화면에서 실행한다 |
| 결과 송부 | 2주 이내에 보낸다 | 질문 직후 답 화면과 보고서 PDF가 나온다 |

- 사용자는 두 부류다. 1차 사용자는 센터를 찾은 소상공인·예비창업자(도민)이고, 2차 사용자는 센터 담당자다.
- Agent는 창업할지 말지 추천하거나 결정하지 않는다. 판단에 쓸 근거(숫자·순위·출처·한계)를 보여 준다.

## 2. 구조

### 2.1 처리 순서
1. **M1 질문 해석**: 문장 임베딩(Ollama `bge-m3`) + 분류기로 주제·동네·업종을 뽑는다. 임베딩을 쓸 수 없으면 사전 규칙으로 해석한다.
2. **M2 계획 · M3 작업 지시서**: 주제에 맞는 표와 계산 순서를 정한다.
3. **Sub 실행(S1~S6)**: 조회, 기술 통계, 예측 모델, 차트, 결합, 통계 판정을 Python 코드로 계산한다.
4. **검수**: 설명 문장 속 숫자를 계산값과 대조하고, 다르면 숫자표로 바꾼다.
5. **결과 생성**: 결론 한 줄, 5칸 요약, 근거 차트, 출처, 보고서 PDF를 만든다.

### 2.2 Workflow와 Agent
- 일반 질문은 정해진 순서로 도구를 실행한다(Workflow). 숫자 계산을 LLM에 맡기지 않아 같은 질문에 같은 숫자가 나온다.
- 전문가 모드는 Claude가 분석 계획과 pandas 코드를 정한다. 코드 검사나 실행이 실패하면 오류를 받아 고쳐 다시 제출한다(Agent).
- 구분 기준은 Anthropic, *Building effective agents*(2024-12-19)의 정의를 따른다.

### 2.3 Tool/API

| 도구·API | 고르는 쪽 | 하는 일 | 실패하면 |
|---|---|---|---|
| M1 해석(`bge-m3`, Ollama) | 프로그램 | 질문 → 주제·동네·업종 | 사전 규칙 |
| M3 작업 지시서(`app/runner.py`) | 프로그램 | 주제 → 계산 순서 | 일부만 답하고 이유 표시 |
| S1~S6 계산 도구 | 작업 지시서 | 표 조회·통계·예측·판정 | 그 칸에 이유 표시 |
| 통계 기법 8종(`app/techniques.py`) | 프로그램 | 상관·군집·시계열 분해·회귀·두 집단 검정·분포·이상치·변화 분해 | 적용 조건 미충족 시 계산하지 않고 이유 표시 |
| `submit_plan_text` | 프로그램 | 계획 설명 한 문장 | 정해진 문장 틀 |
| 검수(`app/textcheck.py`) | 프로그램 | 문장 속 숫자 대조 | 숫자표로 대체 |
| `submit_analysis` | Claude | 분석 계획·pandas 코드 | 오류를 받아 고쳐 다시 제출 |
| 코드 검사·분리 실행(`app/sandbox.py`) | 프로그램 | 별도 프로세스, 20초·결과 1MB 상한 | 실행 중단, 이유 표시 |
| `submit_explanation` | Claude | 실행 결과 해설 | 숫자표만 표시 |
| 설명 문장 LLM | 프로그램 | Claude → Ollama `qwen3:1.7b` 순서 | 정해진 문장 틀 |

### 2.4 자율 범위

| 누가 정하는가 | 정하는 일 |
|---|---|
| Agent | 질문 해석, 자료 선택, 분석 경로, 되묻기, 전문가 모드의 분석 계획·코드 |
| 프로그램(Python 코드) | 모든 숫자 계산, 예측 검증 기준(오차 비율 1 미만·p < 0.05), 코드 실행 허용 범위 |
| 사람(도민·센터 담당자) | 창업 여부 같은 추천·결정, 전문가 모드 실행 요청 |

## 3. 검증

| 항목 | 방법 | 결과 |
|---|---|---|
| 질문 해석 | 개발자(Claude)가 보지 않은, 다른 검토자(Gemini)가 만든 150문항 | 임베딩 113/150(75%), 사전 규칙 94/150(63%) |
| 다음 7일 하루 방문 예측 | 과거 3개 시점에서 7일 예측해 실제 값과 비교 | 오차 비율 0.67(기준 예측 대비), 80% 예측 범위 적중 78~83% → 답에 표시 |
| 다음 달 업종 카드 매출 예측 | 같은 방식 | 오차 비율 0.99, 기준 예측과 차이 유의하지 않음 → 답에 표시하지 않고 작년 같은 달 값만 보임 |
| 비슷한 동네 5곳(k-NN) | 2024·2025 결과 비교 | 이웃 유지 85% |
| 계절 패턴 군집(k-means) | 실루엣, 두 해 ARI | 0.358 · 0.442 |
| 통계 기법 8종 | 기법을 지정한 8문항 | 요청 기법으로 답함 8/8 |
| 전문가 모드 | 정상 질문 10개, 위험 코드를 쓰도록 요청한 5개(claude-opus-5-5) | 정상 10/10 성공(1차 9개, 결함 수정 뒤 10개), 위험 코드 실행 0건, 응답 중앙값 41.7초·최대 73.1초 |
| 단위 시험 | `python -m unittest discover -s tests` | 159개 통과(2026-11-13, 33.1초) |
| 화면 시험 | Playwright, PC(1280×900)·폰 두 크기 | 118개 통과(2026-11-13, 36.5초) |
| Windows 실행 | 설치·실행 스크립트 | 이상 없음(2026-11-13) |

- 오차 비율(MASE)은 모델 오차를 기준 예측(작년 같은 날·같은 달 값) 오차로 나눈 값이다. 1 미만이면 모델이 기준 예측보다 정확하다.
- 숫자 재현: 같은 표(`data/tables/`)와 같은 코드면 같은 숫자가 나온다. 예측 모델은 `models/recipes.json`의 설정으로 학습한다.

## 4. 한계

| 한계 | 근거 | 다음 개선 과제 |
|---|---|---|
| 세부 업종 매출이 없다 | 카드 자료는 업종 대분류 5개만 제공 | 센터 자료 넣기(CSV)로 세부 업종 매출 계산 시험 |
| 질문 해석 오류가 있다 | 규칙 63%, 임베딩 75%(150문항) | 해석 예시 문장을 늘리고 150문항으로 다시 측정 |
| 예측하지 못하는 지표가 있다 | 업종 월 매출 예측 오차 비율 0.99 | 자료 기간이 늘면 다시 검증 |
| 전문가 모드 실행 분리 수준 | 코드 검사·시간·메모리 상한의 프로세스 분리. 운영체제 수준의 완전한 격리가 아님. macOS에서는 메모리 상한이 걸리지 않음 | 컨테이너 방식 분리 |
| 임대료·권리금 자료가 없다 | 공개 자료에서 찾지 못함 | 공개 출처 조사 |
| 정류소는 이름으로 동네에 잇는다 | 같은 이름이 떨어진 곳에 있으면 구분하지 못함 | 좌표 기반 연결 |
| 센터 PC 실기에서 실행하지 않았다 | 개발 PC(macOS)와 Windows PC에서만 시험 | 센터 PC 설치 시험 |

## 5. 센터 활용 방안
- **센터 PC 탑재**: `scripts\setup_windows.bat`으로 한 번 설치하고 `scripts\run_windows.bat`으로 실행한다. 인터넷 없이 표 파일과 PC에 설치한 모델로 동작한다. 방문자가 바뀌면 창을 닫거나 사이드바 '새 상담 시작'을 누른다.
- **도민 방문 상담**: 도민이 동네와 업종을 골라 결과와 보고서 PDF를 먼저 확인한다. 결과로 해결되지 않는 요청만 담당자 면담으로 넘긴다.
- **담당자 컨설팅**: Agent 보고서를 면담 자료와 결과 초안으로 쓴다. 추가 분석은 사이드바 '통계 기법으로 보기'와 전문가 모드로 화면에서 실행한다.
- **센터 자료 연결**: 화면의 '자료 요청' 카드가 필요한 센터 자료와 조회 조건을 안내한다. 담당자가 센터 PC에서 조회한 CSV를 '센터 자료 넣기'로 넣으면 그 자료로 다시 계산한다.
- **Claude 키(선택)**: 키가 있으면 설명 문장과 전문가 모드에 Claude를 쓴다. 키에는 사용 한도를 먼저 설정한다.
