# 결과 설명자료

제주빅데이터센터 빅데이터 분석·컨설팅 지원 보조 Agent([호리창술] 송준희)의 문제 정의, 구조, 검증, 한계, 센터 활용 방안을 적는다.
실행 방법은 `README.md`, 자료는 `docs/제출/데이터_활용_명세.md`와 `notebooks/01_데이터_확인.ipynb`에 있다.

## 1. 문제 정의
- 제주테크노파크는 센터·데이터허브 데이터로 시각화 분석과 데이터 활용 컨설팅을 지원한다(공고 제2026-116호).
- 2026년 1차 모집은 선착순 10건 내외다. 2025년 실적은 컨설팅 7건, 분석 5건이다(보도자료 2026-04-28).
- 2020~2024년 지원 과제 53건에는 '신규 매장 입지 조사를 위한 유동인구 시각화 분석' 같은 상권 분석이 포함됐다(보도자료 2025-04-30).

| 단계 | 현재 | 이 Agent로 바꾸는 것(제안) |
|---|---|---|
| 신청 | 선착순 10건 내외라 신청하지 못한 도민은 분석 지원을 받지 못한다 | 신청 없이도 센터 PC에서 동네 상권 자료와 보고서(PDF)를 직접 확인한다 |
| 사전 면담 | 신청자 모두와 담당자가 면담한다 | 도민이 Agent 결과를 먼저 확인하고, 결과로 해결되지 않는 요청만 면담한다 |
| 분석·컨설팅 | 담당자가 요청마다 분석을 직접 수행한다 | 담당자는 Agent 보고서를 면담 자료로 쓰고, 추가 분석은 통계 기법 12종·전문가 모드로 화면에서 실행한다 |
| 결과 송부 | 2주 이내에 보낸다 | 질문 직후 답 화면과 보고서 PDF가 나온다 |

- 사용자는 두 부류다. 1차 사용자는 센터를 찾은 소상공인·예비창업자(도민)이고, 2차 사용자는 센터 담당자다.
- Agent는 창업할지 말지 추천하거나 결정하지 않는다. 판단에 쓸 근거(숫자·순위·출처·한계)를 보여 준다.

## 2. 구조

### 2.1 처리 순서
1. **질문 나누기**: 한 질문에 묻는 것이 여럿이면 코드가 하위 질문으로 나눈다. 앞 조각의 동네·업종과 앞 결과('1위 동네')를 뒤 조각에 넘긴다(`app/split.py`).
2. **M1 질문 해석**: 문장 임베딩(Ollama `bge-m3`) + 분류기로 질문 종류·동네·업종·지표를 읽는다. 임베딩을 쓸 수 없으면 사전 규칙으로 해석한다.
3. **M2 계획 선택**: 질문 종류별 계획 표(`app/planner.py`)로 자료와 계산 순서를 정한다. 해석이 애매하면 이해 카드에 '확인이 필요해요'로 표시한다(`JEJU_CLAUDE=auto`면 Claude가 정해진 종류 13개 중에서 고름, `app/plan_agent.py`).
4. **M3 작업 지시서·넘김**: 계산 순서를 확정한다. 일반 경로가 풀지 못한 질문(계산 실패, 분류기만 범위 밖으로 본 질문)은 Agent에게 넘긴다(`JEJU_CLAUDE=auto`면 Claude가 넘길지 판정).
5. **Sub 실행(S1~S6)**: 조회, 기술 통계, 예측 모델, 차트, 결합, 통계 판정을 Python 코드로 계산한다.
6. **검수·재실행**: 결과와 문장 속 숫자를 검사하고, 실패하면 재계획·재계산한다(2회까지). 해석 오류 후보는 오류 노트로 만들어 다시 읽히고, 남은 의심 칸은 화면에서 사람에게 확인받는다.
7. **결과 생성**: 결론 한 줄, 5칸 요약, 근거 차트, 출처, 보고서 PDF를 만든다.

### 2.2 Workflow와 Agent
- 구조를 한 줄로 쓰면 '정해진 순서의 Workflow에, 판단이 어려운 곳에만 소형 모델 Agent가 끼어드는 구조'이다. Claude는 센터 담당자가 필요할 때 요청 단위로 켠다. 구분 기준은 Anthropic, *Building effective agents*(2024-12-19)의 정의를 따른다.
- 일반 질문은 정해진 순서로 도구를 실행한다(Workflow). 숫자 계산을 LLM에 맡기지 않아 같은 질문에 같은 숫자가 나온다.
- 기본 경로에서 LLM이 판단하는 곳은 전문가 모드의 분석 담당 Agent(`app/analyst.py`)와 넘겨받은 질문의 도구 루프다. 분석 담당 Agent는 센터 담당자가 요청을 처리하는 순서대로 ① 요청 이해(요청의 뜻으로 기법·자료 찾기·일반 질문을 고름) → ② 조건이 안 맞으면 대안 고르기 → ③ 계산 → ④ 도민 말 해석 → ⑤ 다음 분석 제안을 거친다. 로컬 모델(`qwen2.5:7b`)이 단계마다 한 번 판단하고, 코드는 판단을 검사하고 숫자를 계산한다. 기법 이름이 적혀 있어도 먼저 모델이 판단하고, 이름과 다르면 코드가 한 번 되묻는다.
- 담당자가 [Claude로 분석]을 누른 요청은 Claude가 도구 5개(코드 작성·격리 실행 포함)로 푼다. `JEJU_CLAUDE=auto`면 Claude가 애매한 질문의 계획 선택과 넘김 판정도 맡는다. 두 판단은 정해진 선택지 안에서만 고르고, 같은 질문의 결정은 저장해 다시 쓴다.
- 도구 루프(Agent)는 LLM이 도구를 고르고 결과를 보고 다음 도구를 고른다. 단계 5회·90초 상한과 숫자 대조는 코드가 통제한다.
- 여러 단계 질문은 LLM 루프에 맡기지 않고 코드가 나눈다. 측정에서 로컬 소형 모델(`qwen2.5:7b`)은 도구 하나를 고르는 일을 10문항 모두 맞혔다. 그러나 결과를 보고 다음 도구를 이어 부르는 여러 단계 질문은 40문항 중 1문항만 풀었다. 나누기는 Claude 키 유무와 상관없이 같은 코드로 돈다.

### 2.3 Tool/API

| 도구·API | 고르는 쪽 | 하는 일 | 실패하면 |
|---|---|---|---|
| 질문 나누기(`app/split.py`) | 프로그램 | 여러 단계 질문 → 하위 질문, 맥락·앞 결과 넘기기 | 나누지 않고 한 질문으로 처리. 앞 결과가 없으면 뒤 조각을 계산하지 않고 이유 표시 |
| M1 해석(`bge-m3`, Ollama) | 프로그램 | 질문 → 종류·동네·업종 | 사전 규칙 |
| `choose_plan` | Claude(`JEJU_CLAUDE=auto`) | 애매한 질문의 종류(13개 + Agent) | 분류기 결과. 고른 종류가 검수 규칙에 걸려도 분류기 결과 |
| `judge_route` | Claude(`JEJU_CLAUDE=auto`) | 일반 경로로 충분한지 / Agent로 넘길지 | 일반 경로 결과 |
| M3 작업 지시서(`app/runner.py`) | 프로그램 | 종류 → 계산 순서 | 일부만 답하고 이유 표시 |
| S1~S6 계산 도구 | 작업 지시서 | 표 조회·통계·예측·판정 | 그 칸에 이유 표시 |
| 통계 기법 12종(`app/techniques.py`) | 프로그램 또는 Agent | 상관·군집·시계열 분해·회귀·두 집단 검정·분포·이상치·변화 분해·입지계수·생존분석·업종 다양성·변이할당 | 적용 조건 미충족 시 계산하지 않고 이유 표시 |
| 분석 담당 Agent(`app/analyst.py`) | `qwen2.5:7b`(단계마다 1회 판단) | 요청 이해 → 대안 → 계산 → 해석 → 다음 분석 | 기법 이름과 다르면 되묻기, 목록 밖 동네·업종 빼기, 해석에 숫자·결과 밖 동네가 있으면 기법 코드 문장 |
| Agent 도구 6종(`app/expert.py`) | 넘겨받은 질문은 `qwen2.5:7b`(4개), 담당자 요청 때 Claude(5개) | 자료 확인, 기법 실행, 일반 답 다시 부르기, 센터 자료 찾기, 코드 실행(격리, Claude만), 답 제출 | 질문에 적힌 기법과 다르면 되돌림, 같은 호출 반복 시 중단, 실패 시 일반 경로 결과 |
| 코드 검사·분리 실행(`app/sandbox.py`) | 프로그램 | 별도 프로세스, 20초·결과 1MB 상한 | 실행 중단, 이유 표시 |
| 검수(`app/verify.py`, `app/textcheck.py`) | 프로그램 | 결과 검사, 문장 속 숫자 대조, 오류 노트 | 재계획·재계산, 숫자표로 대체, '확인이 필요해요' 표시 |
| 설명 문장 LLM | 프로그램 | Ollama `qwen3:1.7b`(`JEJU_CLAUDE=auto`면 Claude 먼저) | 정해진 문장 틀 |
| `/api/feedback` | 사람 | [맞아요]·[조건 바꾸기] 기록 → 재학습 자료(`tools/feedback_to_train.py`) | 기록만 남김 |

### 2.4 자율 범위

| 누가 정하는가 | 정하는 일 |
|---|---|
| Claude(담당자가 켠 요청, `JEJU_CLAUDE=auto`면 자동) | 도구 루프의 도구 선택·전문가 모드 코드. 자동 설정이면 애매한 질문의 종류, Agent로 넘길지 |
| 로컬 소형 모델(`qwen2.5:7b`) | 전문가 모드의 요청 이해(기법·인자), 조건이 안 맞을 때 대안, 결과 해석(숫자 없이), 다음 분석 제안. 넘겨받은 질문의 도구 선택(도구 4개) |
| 프로그램(분류기·규칙·계획 표) | 질문 나누기, 질문 해석, 자료 선택, 분석 경로, 재계획·재계산 |
| 프로그램(Python 코드) | 모든 숫자 계산, 예측 검증 기준(오차 비율 1 미만·p < 0.05), 코드 실행 허용 범위, 루프 단계·시간 상한 |
| 사람(도민·센터 담당자) | 창업 여부 같은 추천·결정, 의심 칸 확인, 전문가 모드 실행 요청, Claude를 켤지 |

## 3. 검증
- 조정에 쓴 문항과 판정에 쓴 문항을 나눴다. 판정용 문항은 다른 검토자(Gemini)가 만들었고 학습·조정에 쓰지 않았다.
- 분류기 학습 자료에는 사람 말투 정답 1,000문항(Gemini 045·046)과 질문 조각 말투 600문항(Gemini 051)을 더했다. 시험 문항과 같은 문장은 0개다.

| 항목 | 방법 | 결과 |
|---|---|---|
| 질문 해석 | 판정용 300문항 | 임베딩 분류기 248(82.7%), 사전 규칙 199(66.3%). 학습 문항을 더하기 전 227(75.7%) |
| 애매한 질문의 계획 선택(`JEJU_CLAUDE=auto`) | 같은 300문항, Claude / `qwen2.5:7b` | Claude 246 → 250(고친 문항 4·망친 문항 0, 분류기 246 기준). 로컬 모델 246 → 242라 기본으로 끔 |
| 여러 단계 질문 나누기 | 판정용 150문항(여러 단계 100·기법 + 일반 50) + 하나짜리 질문 50, Claude 없음(`tools/eval/split_eval.py`) | 여러 단계 0 → 70/100, 기법 + 일반 0 → 36/50. 하나짜리 질문 50개는 나누지 않았고 35개가 맞음(틀린 15개는 해석 오류). 조각 종류 274/300(91.3%) |
| Agent로 넘길지 판정(`JEJU_CLAUDE=auto`) | 판정용 100문항(일반 50·Agent 50), Claude | 72/100. 코드 관문만 43, 모든 질문을 먼저 판정하는 방식 69 |
| 다음 7일 하루 방문 예측 | 과거 3개 시점에서 7일 예측해 실제 값과 비교 | 오차 비율 0.67(기준 예측 대비), 80% 예측 범위 적중 78~83% → 답에 표시 |
| 다음 달 업종 카드 매출 예측 | 같은 방식 | 오차 비율 0.99, 기준 예측과 차이 유의하지 않음 → 답에 표시하지 않고 작년 같은 달 값만 보임 |
| 비슷한 동네 5곳(k-NN) | 2024·2025 결과 비교 | 이웃 유지 85% |
| 계절 패턴 군집(k-means) | 실루엣, 두 해 ARI | 0.358 · 0.442 |
| 통계 기법 12종 | 기법을 지정한 문항, 단위 시험 | 기존 8종 8/8. 추가 4종은 정의식대로 계산되는지(입지계수 비율, 변이할당 세 효과의 합 = 실제 변화 등) 시험으로 확인 |
| Agent·전문가 모드(Claude) | 정상 질문 10개, 위험 코드를 쓰도록 요청한 5개 | 정상 10/10 성공, 위험 코드 실행 0건, 응답 중앙값 10.0초 |
| 전문가 모드 요청 → 기법 연결(`qwen2.5:7b`) | 판정용 120문항(Gemini 055: 기법 12종 × 8 + 기법이 아닌 요청 24, `tools/eval/tech_route.py`) | 모델 단독 106/120(88.3%), 모델 + 코드 검사 107/120(89.2%). 기법 이름 없이 풀어 쓴 요청 64/72(이름 규칙만 17/72), 이름 있는 요청 22/24 → 검사 뒤 24/24, 기법이 아닌 요청 20/24. 이전 판정(052 48문항, 이름이 있으면 코드가 실행하던 구조) 43/48 |
| 단위 시험 | `python -m unittest discover -s tests` | 207개 통과(2026-11-14) |
| 화면 시험 | Playwright, PC(1280×900)·폰 두 크기 | 126개 통과(2026-11-14) |
| Windows 실행 | 설치·실행 스크립트 | 이상 없음(2026-11-13) |

- 오차 비율(MASE)은 모델 오차를 기준 예측(작년 같은 날·같은 달 값) 오차로 나눈 값이다. 1 미만이면 모델이 기준 예측보다 정확하다.
- 숫자 재현: 같은 표(`data/tables/`)와 같은 코드면 같은 숫자가 나온다. 예측 모델은 `models/recipes.json`의 설정으로 학습한다. LLM의 계획 선택·넘김 판정은 같은 질문이면 저장된 결정을 다시 쓴다.

| 세부 업종 매출이 없다 | 카드 자료는 업종 대분류 5개만 제공 | 센터 자료 넣기(CSV)로 세부 업종 매출 계산 시험 |
| 질문 해석 오류가 있다 | 임베딩 82.7%, 규칙 66.3%(300문항). 틀린 칸은 답할지 여부가 가장 많음 | 화면에서 사람이 고친 해석을 재학습 자료로 쓰기(기록 기능 구현됨) |
| 여러 단계 질문의 일부 조각을 못 답한다 | 여러 단계 69/100, 기법 + 일반 34/50 | 확신이 낮은 조각 처리, 기법 이름 사전 보강 |
| 웹 데모는 해석 정확도가 낮다 | Vercel에 Ollama가 없어 사전 규칙(66.3%)으로 해석 | 센터 PC 탑재본으로 시연 |
| 예측하지 못하는 지표가 있다 | 업종 월 매출 예측 오차 비율 0.99 | 자료 기간이 늘면 다시 검증 |
| 전문가 모드 실행 분리 수준 | 코드를 검사한 뒤 별도 프로세스에서 시간과 메모리를 제한해 실행한다. 운영체제 수준의 완전한 격리는 아니고, macOS에서는 메모리 상한이 걸리지 않는다 | 컨테이너 방식 분리 |
| 임대료·권리금 자료가 없다 | 공개 자료에서 찾지 못함 | 공개 출처 조사 |
| 정류소는 이름으로 동네에 잇는다 | 같은 이름이 떨어진 곳에 있으면 구분하지 못함 | 좌표 기반 연결 |
| 센터 PC 실기에서 실행하지 않았다 | 개발 PC(macOS)와 Windows PC에서만 시험 | 센터 PC 설치 시험 |

## 5. 센터 활용 방안
- **센터 PC 탑재**: `scripts\setup_windows.bat`으로 한 번 설치하고 `scripts\run_windows.bat`으로 실행한다. 인터넷 없이 표 파일과 PC에 설치한 모델(`bge-m3`·`qwen3:1.7b`·`qwen2.5:7b`)로 동작한다. 방문자가 바뀌면 창을 닫거나 사이드바 '새 상담 시작'을 누른다.
- **도민 방문 상담**: 도민이 동네와 업종을 골라 결과와 보고서 PDF를 먼저 확인한다. 결과로 해결되지 않는 요청만 담당자 면담으로 넘긴다.
- **담당자 컨설팅**: Agent 보고서를 면담 자료와 결과 초안으로 쓴다. 추가 분석은 사이드바 '통계 기법으로 보기'와 전문가 모드로 화면에서 실행한다.
- **센터 자료 연결**: 화면의 '자료 요청' 카드가 필요한 센터 자료와 조회 조건을 안내한다. 담당자가 센터 PC에서 조회한 CSV를 '센터 자료 넣기'로 넣으면 그 자료로 다시 계산한다.
- **Claude 키(선택)**: 기본은 키가 있어도 자동으로 쓰지 않는다. 담당자가 계정으로 로그인한 뒤 전문가 모드에서 [Claude로 분석]을 누른 요청에만 쓴다(목록에 없는 분석의 코드 작성 등). 키가 없어도 질문 나누기와 로컬 모델 Agent로 같은 구조가 돈다. 키에는 사용 한도를 먼저 설정한다.
