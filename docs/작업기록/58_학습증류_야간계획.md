# 58번 학습 증류 야간 검토 계획 (2026-11-17 착수)

마스터 지시(노션 58번 2026-11-17): "학습 증류 : 야간 재검토 계획 착수". 목적은 56·59번과 같다. 7B가 질문의 분석 흐름을 이해해 알맞은 통계 기법을 고르게 한다.

## 1. 정의와 비교 대상
- 학습 증류: 교사 모델의 출력(의도·흐름·기법·이유)으로 학생 모델(qwen2.5:7b)을 LoRA로 미세조정한다. 예시 증류(프롬프트에 예시를 넣음)와 달리 지식이 모델 가중치에 들어간다.
- 근거: Distilling Step-by-Step(arXiv 2305.02301)은 교사의 이유(rationale)를 함께 학습시키면 작은 모델이 적은 자료로 큰 모델을 넘는다고 보고한다.
- 비교 기준(같은 판정 309문항, 같은 쓸모 판정): 코드 표 / 예시 증류(범위 점검 포함) / 학습 증류.

## 2. 확인한 조건(11/17 밤)
- Mac: RAM 64GB, mlx_lm 0.32.2(`/Volumes/1TB/local_store/jeju_lora/venv`), llama.cpp(`convert_hf_to_gguf.py`, `convert_lora_to_gguf.py`), `llama-quantize`, 디스크 여유 793GB.
- 원본 가중치: Qwen/Qwen2.5-7B-Instruct 내려받는 중(HF_HOME=/Volumes/1TB/local_store/huggingface).
- 11/11 X1 실험: Qwen3-1.7B LoRA(질문 해석)가 기존 방식과 정확도 차이가 유의하지 않았고(p = 1.0·0.085) 느렸다. 이번에는 과제가 '기법 고르기'로 좁고, 출력이 짧다.

## 3. 마스터가 정할 것(학습 전에)
1. 교사 출력의 사용 조건: Anthropic 소비자 약관은 서비스를 경쟁 제품 개발이나 AI·ML 모델 학습에 쓰는 것을 제한하는 조항이 있다(https://www.anthropic.com/legal/consumer-terms). Opus가 만든 교사 라벨로 7B를 학습시키는 것이 해당하는지는 마스터 판단이 필요하다(Claude는 법률 판단을 하지 않음).
   - 대안: 로컬 qwen2.5:14b(Apache-2.0)를 교사로 쓴다. 먼저 14b가 예시 증류 방식으로 고른 기법의 쓸모를 재서 교사 품질을 확인한다.
2. 배포 형태: 센터 PC는 VRAM 3GB라 7B 두 개를 번갈아 올리면 교체 지연이 크다. 학습한 모델이 기법 고르기만이 아니라 모든 역할(질문 해석·단계 계획·도구 선택)을 맡아야 한다. 그래서 다른 역할이 나빠지지 않게 기존 역할의 7B 응답을 함께 학습시키고(자기 증류, arXiv 2402.13669), 전체 회귀 시험을 다시 돌려야 한다.

## 4. 단계(검증 방법)
1. 파이프라인 점검: 작은 LoRA(수십 걸음)를 학습 → 합침(mlx_lm fuse, de-quantize) → GGUF 변환 → Q4_K_M 양자화 → `ollama create` → 응답 확인. 검증: 변환한 모델이 기존 qwen2.5:7b와 같은 질문에 같은 형식으로 답하는지.
2. 학습 자료: 교사 라벨(조정용 일반 304) + 합성 도민 질문 약 600(교사가 질문과 라벨을 함께 씀, 판정 문항과 겹침 검사) + 기존 역할 보존용 7B 자기 응답(조정용 일반·Agent·초보 문항의 계획·도구 선택 출력). 판정 문항은 넣지 않는다.
3. 학습: LoRA rank 8~16, 2~3 epoch(작은 자료에서 과적합 방지), 검증 손실로 멈춤.
4. 조정용 평가: 기법 고르기(flow_eval) + 기존 역할(일반 282·안내 정직성 70·Agent 30·초보 40·기법 132)이 떨어지지 않는지.
5. 판정 1회 + 쓸모 판정(방식 정보 없이). 기준: 쓸모 있는 기법이 있는 문항이 코드 표 이상, 기존 역할 회귀 0, 기법 선택 지연이 예시 증류 이하.
