# 일반 질문 정답 기준(마스터 승인 2026-11-15, A안 원칙 1~4)

정답은 `data/eval/capability_spec.md`(자료 능력 명세)로 **자료로 가능한 가장 맞는 처리**를 정한다. 코드 동작은 보지 않는다.

## 1. 정답 칸(문항 하나)
```json
{"id": "...", "gen": "생성 모델", "split": "dev|judge", "q": "질문",
 "accept": ["답함", "되묻기"],            // 허용 처리 집합(원칙 2). 답함·되묻기·범위밖 중 맞는 것 모두
 "space": ["노형동"],                      // 답함일 때 행정동(없으면 []: 제주 전체 또는 동네 순위)
 "metric_ok": ["5년생존율"],              // 허용 지표(명세 2절 이름). 대체 지표면 그 지표
 "target_ok": ["카페", "음식점"] | null,   // 허용 업종(매출 계열에서 카페는 음식점도 허용)
 "period": null | {"year": 2024} | {"year": 2025, "month": 7} | {"month": 7} | {"recent_months": 3},
 "cond": ["비"],                           // 조건 효과로 답해야 하는 조건
 "order": null | "desc" | "asc",          // 동네 순위를 물으면 방향
 "notice": ["대체 지표" | "제주 전체 값" | "자료 없음" | "센터 자료 필요" | "방문으로 대신"],  // 답에 꼭 밝혀야 하는 것(원칙 3의 ③)
 "ambiguous": false, "why": "정답을 이렇게 본 이유 한 문장"}
```
- '작년'=2025, '올해'=2026. 동네 이름 없이 '가장·어디'를 물으면 순위다(`space` []).
- 업종 생존율처럼 제주 전체 값만 있는 것은 `accept`에 답함(제주 전체)과 되묻기를 함께 넣고 `notice`에 '제주 전체 값'.
- 명세 6절은 범위밖. 5절은 답함(대체 지표 + `notice` '센터 자료 필요').
- 사람마다 정답이 갈릴 질문은 `ambiguous: true`로 두고, 허용 값을 넓게 적는다.

## 2. 채점(원칙 3, 코드: tools/eval/general_answer.py)
| 층 | 기준 |
|---|---|
| ① 처리 | 서비스의 처리(답함·되묻기·범위밖)가 `accept` 안에 있다 |
| ② 요소 | 답함으로 처리했고 `accept`에 답함이 있을 때, 동네·지표·업종·기간·조건·순위 각각 맞음/틀림. 점수 = 맞은 요소 수 ÷ 정답이 있는 요소 수 |
| ③ 안내 정직성 | `notice`가 있으면 답의 안내·한계·결론에 그 사실이 있다(낱말 대조) |
| ④ 완전 정답 | ①이 맞고, 답함이면 ② 모든 요소와 ③이 맞다 |

## 3. 라벨 절차(원칙 4)
- 질문을 만든 모델이 아닌 두 모델이 따로 정답을 붙인다. `accept`·`metric_ok`·`space`가 같으면 확정한다(허용 집합은 합친다).
- 다르면 세 번째 모델이 고른다. 그래도 갈리면 `ambiguous: true`로 두고 주 점수(④)에서 빼서 따로 보고한다.
- 라벨러 사이 일치도(처리 기준 카파)를 보고한다.
